# Slack 3봇 답변 복구 기준 — 2026-09-21

## 문제 정의

실제 been_jobs 질문 세 건 모두 수치 답변에 실패했다. 내부 매출 API 단독 성공은
Slack 경로 성공이 아니었다. 배포된 세 봇은 공통 `dashboard_metrics_client.py`를 호출한다.

1. `핵심만` 등 표현 요청을 미지원 브랜드 조건으로 오인했다.
2. 모든 도메인에 모든 원천의 48시간 검사를 적용해 유튜브 수집 지연이 라이브·광고도 차단했다.
3. fresh YouTube Analytics와 stale 발행 원천을 분리하지 않아 부분 답변도 불가능했다.
4. 테스트가 실제 CLI 검증 경로를 충분히 실행하지 않았다.

## 답변 기준

- 기간·도메인을 해석할 수 있는 일/주/월 성과 질문은 검증된 해당 기간 수치로 답한다.
- `핵심만`, `간단히`, `요약해줘` 같은 독립 표현은 기간·브랜드·포맷 조건을 변경하지 않는다.
- 알 수 없는 브랜드/조건은 전체 합계로 바꾸지 않고 명확하게 되묻는다.
- 공용 캐시 형식, 48시간 빌드 신선도, 기준일, 공개 HTML SHA 검증은 유지한다.
- 라이브는 live_quality, 광고는 revenue_mirror와 포함되는 라이브 관련 원천을 검사한다.
  관련 없는 유튜브 지연이 이 수치를 차단하지 않는다.
- 유튜브 API 조회수는 API 채널·수집시각·실제 집계일을 검증한다. 발행 원천이 지연되면
  조회수와 실제 집계기간만 답하고 발행·D7·구독자는 확인 중으로 표시한다.
- 구독자 질문에는 구독자 상태를 답한다. 조회수로 대신하지 않는다.
- 누락·미집계·귀속 미확인은 0으로 표시하지 않는다. 완료되지 않은 주간 집계를 완료 주로 표시하지 않는다.
- 기본 답변은 수치와 의사결정에 필요한 날짜/조건을 우선하며 출처 URL·DB 이름을 노출하지 않는다.
- 세 봇 모두 실제 been_jobs 질문에 답하고, 응답 수치와 기간이 동일한 검증 엔진 결과와 일치해야 E2E 통과다.
  전송 성공·HTTP 200·테스트 종료코드만으로 통과 처리하지 않는다.

## 확인과 변경 범위

공유 엔진과 회귀 테스트, 운영 문서를 변경한다. 배포는 기존 해시 조건부 원자 교체와 백업을 사용한다.
공통 어댑터는 질문마다 새 엔진을 실행하므로 공통 엔진 교체에는 서비스 재시작이 필요 없다.
별도의 유튜브 주간 경로는 `integrations/youtube_weekly_rules.py`로 릴리스 관리한다.
주간 경로 역시 독립 표현을 허용하고, 인증된 조회수와 편성 확인 상태를 분리하며,
기본 응답은 7줄 이내로 제한한다. 해당 모듈 교체 후 기존 유튜브 봇 프로세스만 재시작한다.
`update_youtube_weekly.py`는 기존 해시 일치, 컴파일, 백업, 원자 교체, 해시 readback을 강제한다.
코드 수정과 원천 최신화는 별도로 검증한다. 자동 갱신 실패를 해결하지 않으면 다시 신선도 한계에
도달할 수 있으므로, 원천 갱신 장애가 남은 경우 완전 복구라고 보고하지 않는다.

테스트 채널: been_jobs (C086M0WDKPC)만 허용.
현재 승인 범위는 세 봇 코드 개선, 필요한 배포 및 해당 채널 질문 테스트다.
원본 DB/Sheet 값, 인증, 크론 일정은 수정하지 않는다.

검증: `python3 -B -m unittest discover -s scripts -p 'test_bot_*.py'`,
`python3 -B -m unittest discover -s scripts -p 'test_youtube_verified_analytics.py'`,
컴파일, 전체 diff 검사, 실제 캐시+공개 HTML readback, 세 봇 Slack 응답 readback.
