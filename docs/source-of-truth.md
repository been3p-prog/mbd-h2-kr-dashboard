# 대시보드 항목별 원천 정의

기계가 소비하는 정의는 [source_contract.json](../data/source_contract.json)이다. 이 문서는 2026년 대시보드의 항목별 의미와 검증 기준을 설명한다. 정의를 추가한 사실만으로 수집·화면 연결·배포가 완료된 것은 아니다. 실제 결과는 해당 실행의 원천 조회, 캐시 검사, 테스트 및 공개 readback으로 입증한다.

## 매출·목표·라이브

| 화면 항목 | 원천 및 기간 | 포함 기준과 주의점 |
| --- | --- | --- |
| 마감예측치·차월 부킹 | `revenue.v_revenue_forecast_monthly`, `ym` | 일반광고는 canonical 비취소 일반광고 부킹, 통광마는 계약 시작월의 계약 금액, 라이브는 확정 편성의 패키지 비용. RAW AF나 비용 원천으로 대체하지 않는다. 3팀 합계와 total/provenance를 검증한다. |
| 마감확정치 | `revenue.integrated_ssot`, `revenue_month` | `include_in_mbd_revenue`의 `team_attributed_revenue`. 일반광고·통합광고·라이브커머스를 3팀에 매핑한다. 명시적 마감 작업만 확정하며 매출 확정과 지연 품질 갱신은 별개다. |
| 현재 RAW 누적 | 일반광고 `booking_pred.revenue`, 통광마 `contract.미셀 매출액`, 라이브 `raw_slots.AF수취액` | 해당 월 cutoff까지 기존 귀속·유상·3P·취소 필터를 유지한다. 통광마는 매출 귀속월과 계약 시작일을 함께 사용한다. 예측과 필터가 다르다. |
| 월 목표 | `meta.targets.value_num` | 해당 `ym`, `metric=매출`, `kind=target`, `ad_gen/ad_int/live`. 전사 다른 라인이나 GMV 목표를 더하지 않는다. |
| 라이브 전체 편성 | `live.raw_slots`, 온에어 일자 | 해당 월 전체. 기존 취소 토큰을 제외하고 무료·미래 편성도 표시한다. 같은 날짜·브랜드의 별도 방송을 임의로 합치지 않는다. |
| 라이브 품질 | 같은 원천의 시청자·1D GMV·1H GMV | cutoff까지 양수 1D GMV, 무료/취소 제외. 매출의 3P 필터와 다르다. 평균은 이 모집단의 1D GMV 합계/건수이며 전체 편성 건수를 분모로 쓰지 않는다. |

구현 근거는 `dashboard_forecast_state.py`, `dashboard_next_booking.py`, `finalize_month_review_from_duckdb.py`, `refresh_live_daily_from_duckdb.py`, `dashboard_live_schedule.py`이다. 2026년 8월 마감의 전월 비교는 코드에 보존된 승인된 7월 baseline을 쓰는 예외가 있다. 해당 값을 새 SSOT 조회 결과라고 표시하지 않는다. 더 오래된 화면에 남은 스냅샷의 현재 원천 정합성은 별도 확인 전에는 **확인 못 함**이다.

## YouTube 편성 원천

- 헤더 6행, 데이터 7행부터, 일정 수집 범위 A:G, 연도 2026, 시간대 Asia/Seoul, 수집 신선도 기준 48시간.

| 열 | 확인한 헤더 | 용도 |
| --- | --- | --- |
| A | ID | 검증된 video ID로 발행 원천에 연결. 비어 있어도 일정 존재를 부정하지 않는다. |
| B | 온에어 일자 | 편성일. 발행 원천의 실제 publish_date와 구분한다. |
| C | 시간 | 편성 시간. 알 수 없는 시간을 임의로 채우지 않는다. |
| D | 지면/포맷 | LF·SF·커뮤니티·라이브. 예정 포맷이 발행 품질 분모를 바꾸지 않는다. |
| E | IP | 승인된 일정 표시 필드. 담당자 신원이나 내부 메모로 대체하지 않는다. |
| F | 콘텐츠명 | 승인된 수기 편성명. 제목으로 실적을 추측 매칭하지 않는다. |
| G | url | 검증된 ID를 얻는 보조 필드. 원문 URL을 무검증으로 링크하지 않는다. |

H:O는 성과 영역이므로 이번 일정 캐시·예정행 지표의 원천으로 사용하지 않는다. 독립 취소 열은 확인되지 않았다. **취소 상태는 확인 못 함**이며 제목, 누락 ID, 색상 또는 이미 지난 예정일을 취소 증거로 간주하지 않는다.

표제·구분·메타데이터 행은 일정에서 제외한다. 날짜만 있는 빈 구좌는 콘텐츠 행과 별도로 집계하여 화면에 요약한다. 포맷이 있으나 콘텐츠명이 없는 행은 미정 구좌로 표시한다. ID가 없는 유효 편성은 남기되 가짜 ID·링크·지표를 만들지 않는다. A와 G의 ID 충돌, 같은 ID의 충돌 일정, 날짜·포맷 파싱 오류를 조용히 버리지 말고 검증 결과에 드러낸다.

발행 결합은 검증된 ID로만 한다. 실제 발행일은 `dim_video.publish_date`가 우선하며 월 경계에서 이미 발행한 영상을 예정행으로 다시 세지 않는다. 예정·발행 확인 대기·미매칭은 각각 실적 수와 구분한다. 미발행·미매칭 지표는 `—`다. 시트에서 삭제·재편성한 항목은 다음 정상 수집에서 캐시와 화면에 반영되어야 한다.

## YouTube 발행과 성과

| 항목 | 원천 | 유지할 의미 |
| --- | --- | --- |
| 실제 발행 목록/수 | `dim_video` | `is_active`이며 해당 기간 cutoff까지 발행된 영상. 예정 목록을 추가해도 이 수는 변하지 않는다. |
| 누적 조회수 | `v_latest_snapshot` | 검증된 ID의 최신 수집값. 일정 제목이나 날짜만으로 가져오지 않는다. |
| D7 조회수·PIS | `fact_analytics_d7` | 기존 완료 여부·수집시각 우선순위의 영상별 행. PIS는 좋아요+댓글+공유이며 미발행행에 계산하지 않는다. |
| D7 평균·LF/SF 품질 | `dim_video`와 완료된 D7 행 | 완료된 실제 발행 cohort를 분모로 사용한다. 예정 커뮤니티/라이브는 제외한다. 실제 기타 포맷은 기존 cohort 규칙을 따른다. |
| 구독자 | `v_channel_daily_subscribers` | 기존 월별 최신값 및 빈 현재월의 carry-forward 규칙을 유지한다. |
| 채널 월/주 성과·D+N 상세 | `v_youtube_monthly_analytics`, `v_youtube_weekly_analytics`, `v_public_dplusn_video` | analytics 기간과 콘텐츠 발행 cohort를 구분한다. 달력 편성 주차가 analytics 집계 기간을 바꾸지 않는다. |

`fact_snapshot`의 날짜는 성과 수집 시계다. 일정 시트의 정상 조회시각이나 원본 수정시각을 대신하지 않는다. `elapsed_weeks`는 경과 주수, `total_weeks`는 해당 월 전체 4~5주 표시 수다. 월초에도 전체 주차를 펼쳐 보이되 미래 주차를 실제 발행으로 세지 않는다.

## 수집·화면 검증

1. registry의 spreadsheet/gid/헤더/연도와 실제 응답을 대조한다. 정상 빈 결과와 API 실패·범위 오류를 분리한다.
2. 원천 응답 → 후보 일정 캐시 → DB 읽기 → 화면 행/빈 구좌 요약의 coverage를 대조한다. 수집시각, 유효·제외·충돌·미매칭 건수를 확인한다. 원문 행·작업메모·인증정보를 공개 manifest에 넣지 않는다.
3. 기존 실제 발행 ID 집합, 발행 수, D7 분모·합계, 기간 KPI가 일정 결합 전후 동일한지 검증한다. 예정일이 최신 발행일을 바꾸지 않아야 한다.
4. 날짜 이동·행 삭제·ID 없는 일정·빈 구좌·중복/충돌·월 경계·미래 지표·반복 갱신·부분 실패를 회귀 검증한다. 화면의 전체 편성 수와 실제 발행 수를 각각 검증한다.
5. 기존 unit/static/contract/browser 검증과 wrapper readback을 유지한다. 링크 개수만으로 전체 편성 또는 실제 발행 수를 추정하지 않는다.
6. 배포가 승인되면 정확한 revision의 공개 결과를 다시 읽는다. 코드·캐시만 준비한 상태는 공개 완료가 아니다. 실패 시 마지막 정상 산출물과 그 신선도 상태를 보존한다.

**확인 못 함**은 근거 부족/조회 실패, **미연결**은 경로 부재, **검증된 없음**은 정상 조회·범위·스키마 검증 후 0건이다. 문서에 새 원천을 등록했다는 이유로 세 상태를 자동으로 연결 완료로 바꾸지 않는다.
